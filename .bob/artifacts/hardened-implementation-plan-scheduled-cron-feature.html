Closed Decisions (pre-implementation)

Decision A maxPRs is NOT per-schedule configurable

Rationale: reviewPRs() reads MAX_PRS_PER_RUN as a module-level constant from the environment. Adding a per-call override requires threading a new parameter through reviewPRs → resolveReviewTargets → fetchPRs — a diff across the most load-bearing code in the project for a feature the user never asked for by name. The user asked to "automate the Review last X PRs capability", where X is already the environment-configured value.

Behaviour: Scheduled runs use the same MAX_PRS_PER_RUN that the manual "Review latest X PRs" button uses. The Settings panel displays this value as a read-only label ("Will review up to X PRs, as configured") so the operator knows what will run without being offered a control that doesn't work.

Decision B Settings modal uses Tabs, not nested Accordion

Rationale: McpConnectionPanel already contains a Carbon Accordion internally ("Enter credentials manually"). Wrapping the whole modal in a second Accordion creates nested AccordionItems — Carbon's focus trap / keyboard nav inside a Modal is not documented for that nesting and has a real regression path for the existing MCP flow.

Behaviour: Modal heading is "Settings", label is "Settings". The body contains a Carbon Tabs component with two tabs: "Carbon MCP connection" and "Scheduled reviews". Each tab renders its panel component full-width. The "Carbon MCP connection" tab is selected by default. The McpConnectionPanel's internal accordion is completely unaffected.

Decision C Idempotency token written before reviewPRs fires

Rationale: If the process is killed between firing and writing the token, that day's run is skipped. That is the correct tradeoff — skipping one day is recoverable (the operator can trigger manually); firing twice posts duplicate comments to every PR in the run, which is not recoverable.

Sequence (mandatory ordering):

1. Check in-memory lastFiredMinute — if matches, return immediately
2. Compute currentMinute = currentEstMinute()
3. If not (enabled && currentMinute === schedule.timeEST[HH:MM]) → return
4. If reviewState.running → log skip, persist skip record, return
5. Write lastFiredMinute = currentMinute to file (atomic rename) ← claim before firing
6. Claim reviewState synchronously (lines 532–537 of server.js verbatim)
7. Call reviewLog.start()
8. Call reviewPRs().then/catch/finally (same pattern as handleReviewTrigger)

Backend Architecture

New File src/api/scheduleManager.js

Persisted state shape (carbon-monitor-schedule.json):

{
  "enabled": false,           // always false on first creation
  "timeEST": "09:00",         // HH:MM in America/New_York
  "lastRunAt": null,          // ISO string, UTC
  "lastRunSkipped": false,    // true if last tick skipped due to running review
  "lastSkipReason": null,     // human-readable string
  "lastFiredMinute": null     // "HH:MM" idempotency token, reset on each new day
}

Exported API:

  • loadSchedule() — reads file, returns defaults on ENOENT, resets-and-returns on parse error
  • getSchedule() — returns current state + computed nextRunAt (UTC ISO)
  • setSchedule(patch) — validates, merges, persists atomically. Returns updated state.
  • startScheduler(reviewPRs, reviewState, reviewLog) — begins 60s tick loop. Performs ICU probe first.
  • stopScheduler() — clears the interval
  • getSchedulePath() — exported for tests (same pattern as mcp.getBobMcpConfigPath())
  • currentEstMinute() — exported for tests; returns "HH:MM" in ET using Intl

ICU probe (called once in startScheduler):

const tz = new Intl.DateTimeFormat('en', { timeZone: 'America/New_York' })
  .resolvedOptions().timeZone;
if (tz !== 'America/New_York') {
  console.warn('[schedule] Intl cannot resolve America/New_York — scheduler disabled');
  icuAvailable = false;
  return;
}

nextRunAt computation: Find the next wall-clock occurrence of timeEST in ET, starting from now. If today's occurrence is in the past (or is this minute, already fired), advance to tomorrow. Convert to UTC ISO string. Pure date arithmetic, no third-party library.

ET formatting helper (shared with Console.jsx):

function toET(isoString) {
  if (!isoString) return null;
  return new Date(isoString).toLocaleString('en-US', {
    timeZone: 'America/New_York',
    month: 'short', day: 'numeric',
    hour: '2-digit', minute: '2-digit',
    timeZoneName: 'short'
  });
}

Test Plan — tests/scheduleManager.test.js

New File tests/scheduleManager.test.js — 12 cases

Follows the exact same harness pattern as mcpConnection.test.js: sandbox HOME + SCHEDULE_STATE_PATH, plain async function test(), zero external dependencies.

  • 1. Missing schedule file returns default state with enabled: false
  • 2. Corrupt schedule file resets to defaults and overwrites the file (not permanently broken)
  • 3. setSchedule rejects an invalid time string ("9:00", "25:00", "09:60", non-string)
  • 4. setSchedule accepts a valid patch and persists it atomically
  • 5. Tick does NOT fire when enabled: false
  • 6. Tick does NOT fire when currentMinute !== timeEST
  • 7. Tick fires when enabled: true, time matches, and lastFiredMinute is different
  • 8. Tick does NOT fire a second time in the same minute (lastFiredMinute idempotency)
  • 9. Tick skips and records skip reason when reviewState.running === true
  • 10. Tick claims reviewState.running = true synchronously before awaiting reviewPRs
  • 11. nextRunAt is in the future relative to a given "now" input
  • 12. ICU unavailability disables the scheduler without throwing (simulated by mocking Intl.DateTimeFormat)

package.json additions:
